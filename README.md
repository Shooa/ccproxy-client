# ccproxy-client

Клиентский установщик для общего Claude-пула (ccproxy).

## Установка одной командой

Получи у администратора персональный ключ (`sk-ant-oat01-...`) и выполни:

```bash
curl -fsSL https://raw.githubusercontent.com/Shooa/ccproxy-client/main/install.sh | sh -s -- <твой-ключ>
```

Перезапусти терминал — `claude` работает через пул. Прямой запуск с личным
логином (мимо пула): `aclaude`.

Что делает установщик:
- ставит шим `~/.ccproxy/bin/claude` (перехватывает `claude`, подставляет
  прокси; переживает авто-обновления Claude Code);
- пишет ключ в `~/.ccproxy/client.env` (0600, машина-локальный);
- добавляет `~/.ccproxy/bin` в PATH (один раз, идемпотентно).

Повторный запуск с новым ключом — обновляет ключ и шим.

## Локальные бесплатные модели (opencode и др.)

Те же ключи работают с OpenAI-совместимым эндпоинтом пула:

```
baseURL: https://cprox.konyaev.me:8787/v1
```

Модели: `piastra-hi-4.1-flash` (1M контекста, дефолт), `glm-5.3-flash`
(алиас), `qwen3.6-35b-a3b`, `ornith-1.5-35b-a3b`, `qwen3.8-flash-next`.
Они не тратят квоту Anthropic и личный бюджет.

## Лимиты

У каждого ключа личный бюджет (скользящие окна, задает администратор).
Расход виден на дашборде пула. `429 ccproxy: key budget …` — исчерпание
окна, отпускает само, время указано в ответе.

## Проблемы

- `ccproxy shim: claude binary not found` — скажи администратору (обнови
  шим повторной установкой).
- Таймауты из домашней сети — включи офисный VPN.
- `OAuth token revoked` после разовой ошибки — просто повтори запрос.
